# 蓝图与程序工作区生命周期

P2蓝图由`BlueprintSessions`管理会话，P3程序由`ProgramSessions`管理会话。控制器只负责命令解析、玩家响应和退出事件；程序调试器仍由既有`ProgramSession`执行。每种服务分别最多64个工作区，每位玩家在同一种服务内最多一个；蓝图公开只读查看和共享编辑同样占用名额。

## 准入与退出

创建、打开、克隆先检查服务是否关闭、玩家是否已有工作区及64名额预算，再执行读取或保存。存储成功后才发布工作区。关闭/断线与这些同步操作使用同一个监视器；已准入操作先完成，再清理会话。正在读取的旧打开请求不能在清理之后重新放回工作区，关闭服务后也不能创建或保存文件。

玩家退出清除工作区。蓝图丢弃未保存结构与撤销历史；程序还丢弃虚拟传感器、资源、信号、seed/tick、断点和解释器执行状态。最后成功保存的文件保持原字节，再次登录需要显式`open`。已准入保存若先于退出，则其成功提交是最后保存版本。插件关闭后需要新的服务实例才能重新打开。

主动`close`仍检查未保存修改；`close discard`明确丢弃，undo回到保存状态后可以正常关闭。创建/克隆失败不占用会话名额；成功的克隆默认私有并保持固定来源。公开蓝图只授予读取，保存继续校验磁盘上的当前编辑权限和base hash；撤销后重开会重新检查许可。

## 保存失败

真实文件写入失败和协作者冲突不替换当前工作区、base hash或撤销历史；程序保留原调试执行状态。成功保存才清除dirty/undo及程序旧执行。原存储格式、schema、hash、文件布局与模拟引擎均未改变。

## 验证范围

本批次新增21项单元测试：11项蓝图、10项程序。覆盖关闭准入、读请求与关闭排序、断线隔离、实际创建/克隆/保存失败、只读/撤销/冲突、脏工作区关闭、64名额和并发最后名额、同玩家并发创建、关闭时保存及断线时创建/克隆。竞态使用真实store监视器和`ThreadMXBean`确认阻塞位置。修复前机械提取的原控制器逻辑有四条失败；该复现不是实服故障记录。

客户端探针`scripts/offline_client_editor_smoke.cjs`连接三名固定身份玩家，操作共享蓝图、公开只读与许可克隆，进行TCP硬断线重连，再核对程序保存值、调试上下文重置及沙盒回放。运行方法：

```sh
python scripts/server_smoke.py --kind paper --server-jar /path/to/paper.jar \
  --plugin-jar stargenesis-paper/target/stargenesis-paper-4.0.0-SNAPSHOT.jar \
  --directory .work/editor-paper --port 25675 --max-players 8 \
  --player-workflow --client-script scripts/offline_client_editor_smoke.cjs \
  --node-modules /path/to/node_modules
```

2026-11-26在Paper1.21.11-132及Folia1.21.11-14上各完成五项检查，三个最终文件跨平台逐字节一致；Java21/25各499项测试通过。四项提取逻辑的失败回归、首次构建中断，以及探针错误坐标被正确拒绝的失败记录均保留，见[本批次证据](evidence/p11/editor-lifecycle/summary.json)。

文件操作仍同步执行，可能延迟其他草稿命令或关闭；这些功能验证不证明生产吞吐、最大关服时延、65人实服容量或跨Folia区域。会话串行范围不提供跨store实例/进程排他。已经取得的内存编辑引用由玩家命令线程使用，不能经关闭服务再保存；本批次不新增插件热重载或真实服务器重启验收。
