# P4 有限通信日志轮换

管理员可执行 `/genesis radio rotate`，需要 `stargenesis.radio` 和默认仅 OP 获得的 `stargenesis.radio.manage`。这是显式、有限分段归档：不自动清除历史、不重用旧身份，也不承诺无限期通信。

## 准入与身份

当前段必须非空、没有待确认消息，并且所有契约均已终局。否则轮换拒绝。在线端点与逻辑 tick 不变，新活动段仍受每步消息额度限制；新消息最早下一 tick 才可确认，不能通过轮换刷新同一步的发送预算。

旧幂等身份仍是固定 `protocol/hash/sender/sequence`。轮换不会为同一身份开放第二次投递：相同收件人和 payload 的重试返回 duplicate，改变收件人或 payload 则拒绝，比较仍忽略 tick。归档完整保存原请求；内存索引保存长度前缀 UTF-8 字段、排序 payload 的 SHA-256 请求摘要。因此跨段请求一致性判断依赖摘要抗碰撞性，不是将所有原消息对象常驻内存。新的 sender 或 sequence 按原规则独立准入。

契约 ID 也永久保留到整个归档链中，不能用新消息 sequence 重新开立同名契约。旧终局状态仍能通过 `radio contract <ID>` 查询，继续只允许原 requester/provider 查看。归档不是结算凭据，不产生真实物品或货币。

## 格式与预算

未轮换的存档继续写 schema v1；第一次成功轮换才将 `radio-state.json` 发布为 schema v2：

```json
{
  "schemaVersion": 2,
  "active": "完整的原 schema-v1 Snapshot 对象",
  "archives": [{"generation": 1, "sha256": "64位小写十六进制摘要", "bytes": 12345}]
}
```

上例说明字段结构，`active` 在实际文件中是对象。归档为 `radio-state.json.archives/segment-0001.json` 至 `segment-0016.json`，每份均是完整 v1 快照。清单按连续代次记录确切 SHA-256 与字节数；摘要证明完整性，不是运营方数字签名或可信备份。

每个活动段仍最多 4,096 条消息证据、8,192 个 radio 事件及 256 个契约。最多归档 16 段；达到上限后拒绝进一步轮换，当前活动段仍按原预算工作。每个文件最多 16 MiB，归档目录最多 96 MiB，为活动文件和一个共享原子写临时文件各保留 16 MiB，总数据文件预算 128 MiB（不含文件系统元数据及空锁文件）。字节预算可能先于段数预算耗尽；这不是 16 个最大尺寸段均可容纳的承诺。

## 发布与失败恢复

所有 load/save/archive 共用同文件旁 `.lock` 的 OS 排他锁。实例记住它所读取的活动文件摘要；写入在锁内比较预期摘要，拒绝旧实例覆盖其他实例已提交的内容。普通保存保留已提交归档前缀，不能把 v2 降为 v1 或省略旧归档。两个实例交错操作时，陈旧实例必须重新加载，不能自动收养另一实例的权威状态。

轮换先准备下一个未引用的固定归档槽，再原子替换活动清单，最后发布内存候选。活动清单替换是提交点。旧段只有尚未保存的 tick 前移时，可将该 tick 与新段在同次提交中保存；不提前 flush。归档或活动发布失败均保留原活动文件、消息/契约内存与在线端点，未保存时钟仍保持 dirty，可重试或正常 checkpoint。

活动清单发布失败最多留下一个下一代准备槽。后续工作改变旧段内容时，只能原子替换该未引用槽，不会不断产生不同 hash 文件名的孤儿；一旦清单引用，归档槽不可覆盖。遗留的正规临时文件使用共享暂存预留，后续写入可清理另一种临时文件；不删除已引用历史、未知文件或目录故障阻塞物。

文件缺失、大小/hash 不符、符号链接、未知目录条目、非法 JSON 类型/版本/pin、跳代或重复引用都拒绝恢复。恢复逐段重演 radio/contract 历史并核对已应用契约消息的 radio 确认证据；归档中若仍有 pending/活跃契约、跨段重复消息 key/契约 ID、引用旧契约，或历史 tick 倒序，同样拒绝。不会忽略损坏段后启动空总线。旧二进制不理解 v2 时应拒绝该文件，不能手工取出 `active` 作为降级迁移。

## 保证范围

安全实现会在每次保存时同步检查归档完整性，磁盘 IO 随保留历史增长；目录锁/CAS 不提供性能隔离。有限容量、文件故障与多进程回归不能证明 Paper/Folia 生产吞吐、跨区域延迟、断电后的文件系统持久性、真人通信体验或无限日志寿命。不得手工删除已提交归档以释放预算；超过预算后的可信迁移/外部归档策略仍待独立设计。
