# StarGenesis 产品与工程契约 v1

产品口号：**玩家发明规则，世界检验发明。** 本契约冻结 P0 的共同边界；不是 P1–P11 已完成声明。

## 玩法目标与当前范围

以结构、有限行为图、协议、契约、组织和实验规则的组合产生玩法。5 分钟修改公共设计并观察反馈，15–20 分钟完成竞技，长期复用发明与跨玩家协作。不得用宠物升级、抽卡、固定任务或数值膨胀替代开放组合。

P0 实现可启动诊断插件、可校验的五种设计格式、模拟接口、守恒账本和能力发现基线。P1 当前包含确定性网格模拟、玩家专属实验 Inventory 界面和模拟检查点。P2 包含带权限的蓝图编辑会话、Paper Inventory 菜单及绑定已保存蓝图的私有虚拟装配练习；它不会修改 Minecraft 世界或真实库存，仍待真实玩家验收。P3 包含有限菜单构建的玩家 typed IR 行为图、编译预览、签名保存和有界实验室运行；编辑草稿与撤销历史使用玩家 PDC 检查点，仍待 Paper/Folia 真人验收。P4 包含有界协议载荷、同服私信队列、可恢复检查点和玩家绑定芯片，并已实现经 BungeeCord 兼容代理转发的跨服务器私信。跨服转发使用 peer 专属 HMAC 密钥、持久发件箱、收件端权限与协议复验及 PDC 去重回执；Paper/Folia 双后端与 Velocity 3.5.1-615 的离线代理流程各 12 项检查通过，证据见 `docs/evidence/p4/paper-retry-window-02-20261124.json` 与 `folia-retry-window-01-20261124.json`；仍待保存周期崩溃耐久性和真人验收。P5 包含确定性封闭生态、有限遗传参数、独立守恒的物质与能量账本、质量平衡反应网络、复合配方工坊及确定性 8×8 栖息地；局部摄取/分解、供给驱动移动和格内繁殖密度反馈均已实现。`ecology/4` 与 v4 检查点保存逐格库存及个体位置，迁移前验证 v1、v2、v3 的旧哈希；100,000 步模拟在 10 次检查点恢复后保持完整快照和账本一致。共享生态组使用独立服务器文件、`ecology-group/1` 校验记录与原子替换，允许最多 8 名成员共同查看和推进，服务器最多保存 128 组；所有者管理成员或解散组，成员可离开。共享组 Inventory 支持分页浏览、在线成员邀请/移除、共同步进和二次确认解散；Paper/Folia 三离线客户端流程各通过 28 项组管理、权限、双重正常重启恢复和个人 v4 PDC 检查。真人协作和长时间/异常保存耐久性仍待评估。此前的 `player-recovery.json` 个人 PDC 证据来自 v3 构建。P6 已实现固定四成员的模拟竞价、订单交付与质量平衡生产，包含守恒虚拟账本、有界二进制恢复 codec、Paper 命令入口、原子服务器检查点服务、开厂前持久组织名册、`factory:frame`/`factory:plate` 配方、每成员持久工位、组织 Inventory 管理菜单及受信 peer 的成员命令转发。工厂所属服务器单独持有账本，远程成员可从受信后端查询订单、竞价、贡献、交付、推进和使用工位；工厂及订单创建和组织管理须在账本所属服务器进行。Paper/Folia 离线 Mineflayer 流程验证组织菜单权限、成员增删、所有者保护、开厂后冻结、两种配方、逻辑步推进、领取、正常重启恢复及确认保存后的强制进程终止恢复。模拟完成最大 72,000 tick，并每 10,000 tick 及终点执行检查点编解码恢复，共 8 次，状态哈希和物质质量一致。证据见 `docs/evidence/p6/paper-production-result.json` 与 `folia-production-result.json`。Paper/Folia 双后端与 Velocity 3.5.1-615 的离线代理流程各 11 项检查通过，证据见 `docs/evidence/p6/paper-proxy-transaction-03-20261124.json` 与 `folia-proxy-transaction-01-20261124.json`；真人四人验收、机器断电和提交前后故障验证仍待完成。P7 竞技格式支持 schema-2 障碍/出生点/目标、`ANY`/`ALL` 胜利条件、连通性和工作量校验、旧格式显式迁移、玩家地图编辑、最新 ACL 检查、不可变发布、管理员审核队列和持久审核结论。P8 增加固定版本的共享竞技房间、玩家 UUID 席位、双队入场、同步回合、冲突等待、超时动作、原子检查点、重启恢复和只读观战视图；Paper/Folia 离线客户端自动流程通过，真人可用性、反作弊和跨服仍待验收。房间与审核存储由服务器拥有，不接触真实世界、物品、领地或货币。
P6 的组织名册最多四人，由组织所有者管理并在工厂创建后冻结。组织 Inventory 菜单显示名册和在线成员，所有者可在开厂前增删成员。生产使用每成员独立工位及质量平衡配方，工位状态随工厂检查点恢复。Paper/Folia 离线 Mineflayer 客户端已验证菜单权限、状态变化和确认保存后的进程终止恢复。模拟完整运行 72,000 tick，并每 10,000 tick 及终点做一次编码/恢复，共 8 次，状态哈希和质量账本保持一致。跨服成员命令现在通过受信 peer 转发到唯一的工厂账本服务器，支持订单查询、竞价、贡献、交付、推进和工位操作；需要显式启用 `factory-relay.enabled`，工厂、组织和订单创建仍由该服务器执行。实际 BungeeCord-compatible Paper/Folia 双端离线代理流程各 11 项检查通过；真人四人体验、机器断电和提交前后故障验证仍待完成。

P9 增加最多 16 笔转账的持久 saga 状态机、分步幂等键、崩溃恢复查询、逆序补偿和有界校验和日志；真实库存/经济适配器仍须提供幂等副作用与可靠查询，目前没有经验证的适配器，真实结算继续禁用。
P10 增加服务器固定 author UUID→Ed25519 公钥的签名设计交换。Paper 将经信任校验的竞技规则送入 P7 审核流程，并把其他已注册设计类型的原始签名包写入有界归档供管理员检查；没有通用插件类加载，也没有绕过规则审核的导入路径。

## 模块与冻结接口

| 模块 | P0 实际责任 | 后续消费者 |
|---|---|---|
| stargenesis-api | 不可变 ID/元数据、SimulationClock/World、输入/结果/事件/预算/ResourceLedger/EventOutbox | 所有模块 |
| stargenesis-design | Blueprint/Program/Protocol/Contract/ArenaRuleset、严格 JSON 编解码、Ed25519 `.sgdesign` 签名交换、SHA-256、显式迁移、Schema/示例 | P2/P3/P4/P7/P10 |
| stargenesis-sim | 单线程时钟、守恒账本、内存 outbox 与 checkpoint 值对象 | P1/P5/P6 |
| stargenesis-integrations | 只读插件清单、版本审计描述符、能力逐项验证和失效隔离 | P9/P10 |
| stargenesis-paper | 生命周期、命令、权限、配置硬限制、设计加载自检 | 玩家入口/区域调度 |

仅创建有代码和测试的模块。Program 文档通过格式验证不代表其算法已经编译/执行。Protocol/Contract 文档本身不提供网络或交易；ArenaRuleset schema-2、`arena/1` 和本地审核/房间服务仍不代表反作弊、观战、多服对局或真人验收已交付。

公共 API 位于 `dev.stargenesis.api`。设计实现位于 `dev.stargenesis.design`；第三方类型不得进入上述 API 或纯模拟。`DesignExchange` 通过 Ed25519 验证签名与受信公钥，验证后的 JSON 仍经过严格 `DesignCodec` 校验。服务器只存储 OP 明确固定的 author UUID→公钥，不信任签名包自行携带的公钥。变更使用提案→增加兼容/迁移测试→合并队列→整仓 verify 的顺序，不由并行工作者随意改签名。

## 身份、版本与可信边界

- DesignId 使用有界 `namespace:path`，拒绝 `..`，不可解释为磁盘路径；AgentId 使用 UUID，其字典顺序为 UUID ASCII 字符串序。
- 文档包含 stable ID、schemaVersion、语义版本、UUID 作者、来源、精确版本/哈希依赖、权限与哈希。集合防御复制并不可变。
- 当前持久格式为 schemaVersion=1。只有显式 v0→v1 迁移；未知版本拒绝，不自动覆盖原文。迁移保留前后哈希，参见 MIGRATIONS.md。
- SHA-256 用于内容完整性和密钥指纹。Ed25519 只证明已知 author UUID 的签名私钥对指定设计签名，不自动授权依赖或发布；P10 服务器信任表仍由 OP 设置和撤销。
- 玩家只能组合服务端审核的有限原语；不接收 Java、命令、反射、文件/网络 IO、任意脚本或无界递归。P0 不执行玩家程序。

## 确定性与线程模型

- SimulationWorld 的权威状态由单个受控工作线程拥有；输入仅通过不可变 StepInput，输出仅通过不可变 StepResult。当前引擎契约为 `genesis-sim/1`。
- tick 是离散逻辑时间，禁止读取墙钟参与结果；种子显式输入。StepInput 按 AgentId、sequence 排序，重复序号拒绝。所有资源以 long 整数计量，溢出必须在写入前失败。
- 后续 P1 必须固定 RNG 算法、地形/动作顺序、状态哈希编码、检查点和回放版本。P0 接口不等于这些引擎算法已经完成。
- Bukkit、helsteraMobs、CraftEngine、实体和背包调用留在适配层，按目标服务器/区域/实体调度。不得把“主线程”解释为 Folia 的全世界同步线程。
- 显示实体仅为模拟投影；不根据其位置、动画或物品外观推导权威模拟状态。

## 资源、幂等与恢复

- 模拟材料、能源、耐久与真实库存/货币是不同资产域。实验得分不能兑付真实物品；P0 没有真实结算路径，配置企图启用时拒绝启动。
- EvidenceId 格式 `sg:v1:<world>:<tick>:<sequence>`；world 不含冒号。用于事件和模拟转移去重，不能直接当作第三方已经支持的幂等参数。
- ResourceLedger 只在初始场景中注入有限资产；随后只能账户间转移，禁止 mint。相同 evidence + 同请求不重复支付；同 evidence + 不同请求拒绝。
- 余额不足也消耗该 evidence；补充余额后须以新 evidence 重试。账本 checkpoint 包含余额与成功/失败历史，恢复后继续去重。容量达到上限时停止，不能删除历史后重用旧键。
- MemoryEventOutbox 是内存参考实现，不具备崩溃持久性。P1 玩家实验室在 PDC 检查点中额外保存有界逐步输入及初始网格基线，并在恢复时确定性重放和比对最终哈希。玩家 PDC 的最终落盘仍由 Paper 玩家数据保存周期负责。真实世界订单必须等 P9 的持久 saga/outbox、补偿和第三方事务证据完成后才启用。

## 权限、预算与公平

实验与竞技不得更改生存建筑、实际库存或他人造物。作者/编辑者权限、克隆授权与来源须在 P2/P7/P10 的每个入口检查；P7 房间只从审核后的固定发布版本启动。审核文件校验校验和、提交身份与最近 ACL，但服务器信任范围仍在单一服务器管理员账户内。

默认预算：每造物每步128节点、16造物、每步8路径请求、最多3000步、感知半径16、每步64消息；硬上限见 SimulationBudget。P0 对配置做校验，后续执行器负责实际计量并给出可理解的超限事件。

公共入门模板免费；核心竞技统一预算。深度提供策略选择，不提供无上限数值优势。离线产出默认关闭；真实收益与榜单须以可复现结果和幂等证据结算。

## 阶段门与并行顺序

P0 基线冻结后：A 负责 P1→P5 模拟，B 负责 P2→P3 创造，C 持续审计适配并在 P9/P10 激活，D 从 P1 补玩法体验。P4 依赖 Program IR 与事件日志，P6 依赖 P4，P7 使用已实现原语，P8 整合成熟系统，P9 依赖真实经济事务，P11 汇总真实集成与玩家验证。

每次合并运行结构/Schema 合同测试、纯 Java 单元测试、正式 `./mvnw -B verify` 和已存在的最小回放。服务器、真实客户端、多人和长期留存是不同证据等级，禁止互相冒充。阶段未通过所列门槛保持未验收。
