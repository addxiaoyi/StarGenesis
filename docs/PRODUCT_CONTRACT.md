# StarGenesis 产品与工程契约 v1

产品口号：**玩家发明规则，世界检验发明。** 本契约冻结 P0 的共同边界；不是 P1–P11 已完成声明。

## 玩法目标与当前范围

以结构、有限行为图、协议、契约、组织和实验规则的组合产生玩法。5 分钟修改公共设计并观察反馈，15–20 分钟完成竞技，长期复用发明与跨玩家协作。不得用宠物升级、抽卡、固定任务或数值膨胀替代开放组合。

P0 实现可启动诊断插件、可校验的五种设计格式、模拟接口、守恒账本和能力发现基线。P1–P8 已有确定性沙盒、创作器、radio/contract、生态、组织工厂、审核后发布的 ArenaRuleset UGC 与多玩家回合竞技代码；Paper/Folia 自动客户端覆盖已实现的玩家命令，真人验收仍逐阶段待完成。P5 自动 parameter profile 扫描验证了 matter 守恒与 replay，四组对照规则在 SNAPSHOT/RC 的 Paper/Folia 实服运行中均在500 tick预算前灭绝；一组固定 seed 52008 candidate 在四次 Paper/Folia SNAPSHOT/RC 运行中都到达500 tick并保留三物种。纯 Java 模拟还对两个归档的 Alice worldId 分别扫描100个 seeds，200/200 到500 ticks时保留三物种，但这不是服务器负载证据。2026-11-25 完成 Paper/Folia 各八 seed 自动客户端实服扩展，16/16 均到500 tick保留三物种，matter 守恒与 replay 校验全部通过。P5 的广泛 seed 稳健性、长期生态平衡与真人验证仍未完成。P9 已有 saga 协调协议和持久文件 repository，但真实结算 adapter 未通过幂等/权限/故障验收，交易保持关闭。P10 有 Ed25519 signed design import、publisher 包签署 CLI 和 OP 管理的 trust-root 添加/轮换/撤销流程，新增Paper限定的Helstera只读模型查询与真实服务生命周期证据，并增加固定依赖清理补丁支持的有界被动实验室模型投影；另有CraftEngine原生脱离背包创建、完整有界NBT恢复、实际重载/跨进程恢复和只读物品命令；尚无运营方真实key、客户端模型/物品资源包外观、生产授权交付或完整系列插件验收。P11 有 CycloneDX aggregate SBOM、15分钟 Folia 受控沙盒负载和 `4.0.0-rc.1` 隔离候选构建；生产规模性能、玩家留存和发行方正式签名验收仍未完成。

## 身份、版本与可信边界

- DesignId 使用有界 `namespace:path`，拒绝 `..`，不可解释为磁盘路径；AgentId 使用 UUID，其字典顺序为 UUID ASCII 字符串序。
- 文档包含 stable ID、schemaVersion、语义版本、UUID 作者、来源、精确版本/哈希依赖、权限与哈希。集合防御复制并不可变。
- 当前持久格式为 schemaVersion=1。只有显式 v0→v1 迁移；未知版本拒绝，不自动覆盖原文。迁移保留前后哈希，参见 MIGRATIONS.md。
- SHA-256 用于内容完整性与依赖固定，不是作者数字签名或授权证明。P10 signed envelope 可证明受信 Ed25519 publisher key 签过内容，但不替代 publisher trust-root 生命周期、设计作者许可或游戏操作授权。
- P10 新公钥准入为每个活跃身份预留撤销空间，active+revoked至多4096且active至多32。信任库完整操作在目录锁内完成；撤销先落盘再清理公钥，已撤销keyId不能复用，已导入内容在每次读取时按当前信任再验证。
- 可选Helstera桥接只在Paper1.21.11主线程访问当前模型注册表和实体。模型结果与实验室帧为有界不可变值，提供方停用后服务注销；不从模型/动画反写模拟。投影要求固定依赖补丁支持创建回滚和拥有实体的清理重试，旧版提供方仅查询；行为注册保持关闭。
- 可选CraftEngine桥接在Paper1.21.11主线程持有实际资源操作lease，重新检查加载/重载/退出与提供方身份。创建返回脱离背包的副本，捕获与恢复保留全部NBT字段、类型、数组/列表顺序及PDC；仅忽略compound字段排列与GZIP表示差异。快照限256 KiB压缩/1 MiB展开/4096节点/32层，数量1–64且遵守实际栈上限；未知或删除的自定义ID、数据版本迁移、解码字段丢失均拒绝。原始快照字节保持，SHA-256仅用于完整性。该接口不授予库存交付、来源或经济权限，见 `CRAFTENGINE_ITEM_BRIDGE.md`。
- 玩家只能组合服务端审核的有限原语；不接收 Java、命令、反射、文件/网络 IO、任意脚本或无界递归。P0 不执行玩家程序。

## 确定性与线程模型

- SimulationWorld 的权威状态由单个受控工作线程拥有；输入仅通过不可变 StepInput，输出仅通过不可变 StepResult。当前引擎契约为 `genesis-sim/1`。
- tick 是离散逻辑时间，禁止读取墙钟参与结果；种子显式输入。StepInput 按 AgentId、sequence 排序，重复序号拒绝。所有资源以 long 整数计量，溢出必须在写入前失败。
- 后续 P1 必须固定 RNG 算法、地形/动作顺序、状态哈希编码、检查点和回放版本。P0 接口不等于这些引擎算法已经完成。
- Bukkit、helsteraMobs、CraftEngine、实体和背包调用留在适配层，按目标服务器/区域/实体调度。不得把“主线程”解释为 Folia 的全世界同步线程。
- 显示实体仅为模拟投影；不根据其位置、动画或物品外观推导权威模拟状态。

P1/P5/P6/P8后台服务在加载状态前取得持久目录所有权，执行器实际终止后释放。关闭先停止准入并等待排空5秒，再取消队列、中断当前操作并等待1秒；超时不报告干净退出，旧任务仍占用目录，新实例拒绝启动。实验室最终检查点保持原工作线程所有权；radio/实验室最终保存失败也不能记录干净退出。未执行命令不持久恢复，已开始操作可能在超时后完成，重启以最后成功原子文件为准。详见`WORKER_LIFECYCLE.md`。

## 资源、幂等与恢复

- 模拟材料、能源、耐久与真实库存/货币是不同资产域。实验得分不能兑付真实物品；P0 没有真实结算路径，配置企图启用时拒绝启动。
- EvidenceId 格式 `sg:v1:<world>:<tick>:<sequence>`；world 不含冒号。用于事件和模拟转移去重，不能直接当作第三方已经支持的幂等参数。
- ResourceLedger 只在初始场景中注入有限资产；随后只能账户间转移，禁止 mint。相同 evidence + 同请求不重复支付；同 evidence + 不同请求拒绝。
- 余额不足也消耗该 evidence；补充余额后须以新 evidence 重试。账本 checkpoint 包含余额与成功/失败历史，恢复后继续去重。容量达到上限时停止，不能删除历史后重用旧键。
- MemoryEventOutbox 是内存参考实现，不具备崩溃持久性。P9 已有持久 saga protocol 和本地 repository；真实世界订单仍须额外通过真实 adapter 的外部幂等、权限、compensation 和第三方故障恢复验收后才启用。
- P9 每个同步推进必须在repository提供的排他范围内完成查询、授权、外部调用和持久状态替换。外部副作用与本地文件不是一个原子事务，写盘失败后仍需权威幂等查询。provider的NOT_APPLIED/NO_EFFECT必须排除仍可能晚到生效的请求，pending或不确定结果返回UNKNOWN/INDETERMINATE；具体要求见 `SETTLEMENT_PROVIDER_CONTRACT.md`。
- P9自动协调器固定包含恢复能力、credits/item资产权威与幂等历史域的同一快照，授权、查询、外部调用和写盘边界检查失效或声明变化。新交易将原始绑定与saga原子保存为schema-v3，普通推进和复核保留绑定；重建协调器也须核对原始域，旧v1/v2未绑定记录可读但不能自动采用当前provider。异常保留原状态，已提交外部结果只在原始域恢复后通过原幂等键查询恢复。复核的三项查询与提交必须保持同一声明，失效不保存部分历史。声明相同不认证资产所有权、证明幂等历史仍存在或替代provider操作lease。
- P9人工复核由独立审核员和单独授权adapter发起，固定saga/review UUID、预期revision和case reference；审核员不能填写资产结果。复核只重新查询付款/交付/退款，在相同排他范围内原子保存结果与审计记录，已确认APPLIED不能被后续缺失查询抹除。未扣款则关闭、已交付则完成、已退款则补偿完成、仅扣款则进入原幂等退款流程；未知或矛盾结果保持停止。16条历史/64 KiB预算不自动清理。当前没有生产授权adapter或命令入口，真实交易继续禁用。

## 权限、预算与公平

实验与竞技不得更改生存建筑、实际库存或他人造物。P2 蓝图默认私有，作者可显式开放只读查看、指定协作者和许可克隆。协作者仅修改结构，保存时以持久文档的当前授权和基准哈希为准；许可、版本、来源/依赖由原作者控制。克隆使用新 ID，副本私有并记录来源作者、版本和精确哈希；publicRead 不能替代 allowClone。P7 草稿同样以持久授权为准，候选文档不可自授权限。蓝图质量、代价和能力是抽象模拟单位，不对应真实材料、物品或实体。作者/编辑者权限、克隆授权与来源须在 P2/P7/P10 各入口检查；仅存在元数据并不构成授权证据。

默认预算：每造物每步128节点、16造物、每步8路径请求、最多3000步、感知半径16、每步64消息；硬上限见 SimulationBudget。P0 对配置做校验，后续执行器负责实际计量并给出可理解的超限事件。

P1 检查点与回放作为同一份证据原子发布，单份4 MiB。保存失败时冻结模拟并重试，不能继续推进或释放活跃席位；最后有效文件不被部分替换。新实验第0步成功保存才替代上一局，取消失败的首次保存不覆盖旧记录。恢复重演全部输入并核对每步事件、哈希和最终完整状态，读取回放不写盘。每100步保存仍允许异常退出回退到最后成功检查点。该机制不产生真实物品或货币。

P3 的程序声明不能扩大主机执行额度。调试与沙盒均按较低的节点预算执行，step/continue不能刷新同次执行的额度；沙盒使用主机时长和消息预算。任一绑定程序失败时，当前tick的世界输入和信号整体不生效。工作区只有保存成功才更新版本基准与清除未保存状态；错误输入、非法编辑和保存失败不会丢弃当前有效草稿。短时程序模拟与调试上下文不承诺跨重启恢复，保存的typed程序保持作者隔离与哈希校验。

P4 消息发送、确认、契约处理与超时以持久保存成功作为生效边界。保存失败不消耗当前消息额度、不移除原信箱消息、不产生隐藏履约或超时；可使用相同幂等键重试。恢复必须同时验证radio消息/ack和契约事件能重现最终状态，不能以单纯字段合法代替历史一致性。在线端点不落盘，离线与重启不会伪造已上线参与者。

P5 默认实验500 tick，可在新建时显式选择1–1536 tick，覆盖最多三个512步寿命周期的观察窗口。预算不保证存活；时长、出生和代数仍有限。既有实验不自动延长，旧回放配置与 commitments 不改写。长期纯模拟研究记录各物种首次灭绝和生命周期计数，不能把“500步仍存活”或单物种延续当作三物种长期共存。

P5新建生态舱使用`genesis-ecology/2`：摄入最多补到繁殖储量阈值，成熟年龄为当前寿命的一半，成功繁殖间隔为寿命四分之一（向上取整）。所有死亡先释放空位，再处理本tick的繁殖；新生个体下一tick才处理。seed、tick和稳定出生序号决定物理随机选择，world ID只绑定身份与证据，不能因玩家UUID不同改变相同实验的物质/种群轨迹。已有年龄和繁殖间隔不因程序编辑或重启被清空。新默认程序采用较长寿命并保留非零突变率，仍不补种、不增发matter、不扩大人口/代数/出生/证据预算。旧v1保留原规则与哈希，不能改标签迁移；详见`ECOLOGY_ENGINE_V2.md`。

P5 参数搜索与扩展研究必须保留全部失败样本和world/seed身份。v1固定搜索的128组参数中只有一组在搜索世界存活到1536步；其8/8初步成功扩大为64组后只有40组保留三物种。该v1 profile仍是研究候选，不是v1默认配置、稳健性证明或阶段验收通过。v2默认配置沿用其部分参数但使用不同生命周期且保留突变，不能沿用v1研究结论。详见 `docs/evidence/p5/balance-search/summary.json`。

P6 组织关系与比赛历史分别持久化。新工厂场次使用独立 UUID，全部四名成员在线且空闲才能开赛；活跃参赛时不能退队或重复参赛。组队、竞价、订单和补偿均先写盘再报告成功，失败保留原状态以便重试。普通成员不能 reset 共享比赛；`stargenesis.factory.manage` 管理员仅能显式清理已结束且订单全部完成或补偿的历史。目录256场/64 MiB、单文件8 MiB，超限不覆盖旧数据。工厂模拟账户不连接真实资产。

P7 克隆必须固定准确来源，发布ID绑定原作者且不可覆盖内置starter。审核决定与目标文档的作者、ID、版本、hash必须一致；仅保存批准决定不代表发布文件已经可用。发布写入失败保留决定，由原审核员恢复；原作者改动已提交草稿后仍须重新提交更高版本。依赖验证覆盖完整许可闭包，以最长路径限制16层，以唯一pin缓存共享分支；重复依赖不能放大为无界解析工作。新作者目录在创建前检查64人预算。

公共入门模板免费；核心竞技统一预算。深度提供策略选择，不提供无上限数值优势。离线产出默认关闭；真实收益与榜单须以可复现结果和幂等证据结算。

P8 每次新比赛使用独立场次 UUID，精确固定规则和 roster，旧回放保留 v1 commitments。查看历史或观战不改变参赛占用；存在活跃参赛时不能重复开赛或退出队伍。每个未结算动作只有其提交者能撤回，已结算回合不可改写。新比赛先根据固定引擎的每轮事件上界、全部pending动作和128名观战者计算终局文件上界，超过8 MiB则在开赛前拒绝并报告可用轮数；不自动截短已发布规则。目录64 MiB容量优先预留给活跃比赛，比赛结束释放未来增长预留；写入仍检查128场/64 MiB目录和8 MiB单场实际大小。已完成历史仅能由具备 `stargenesis.arena.manage` 权限的管理员显式清理，活跃比赛不得清理。旧存档不会因此改写或拒绝读取，但旧版本已放行的超长局仍受原实际文件上限限制。新命令单元测试不等价于实服或真人竞技验收。

## 阶段门与并行顺序
