# P4 信箱生命周期与容量

`VirtualMessageBus` 只为有未确认投递的收件人保留信箱。加入网络不创建空信箱，最后一条消息确认后立即移除信箱；待确认计数直接读取投递列表，避免独立计数表残留。玩家退出仅注销在线端点，有待确认消息的离线信箱继续保留。重新加入时仍检查当前安装的协议，重启不会恢复在线端点。

| 边界 | 上限或行为 |
|---|---|
| 同时在线端点 | 64；退出释放名额 |
| 单个收件人未确认消息 | 64；确认释放投递空间 |
| 保留的消息幂等证据 | 4,096；确认不释放 sequence |
| 保留信箱 | 每个至少一条未确认消息，因此不超过 4,096；可以多于在线端点数 |
| Radio 发送与确认事件 | 8,192；4,096 条消息全部确认后仍可恢复 |
| 保留的契约 | 256；终局记录不自动删除 |
| 单文件 | 16 MiB；原子写入，失败不发布候选状态 |

`RadioService` 的候选复制、写盘成功后发布和失败重试规则不变。信箱列表在候选之间独立；未轮换存档仍使用 schema v1。没有自动清除历史或重用 sequence 的行为：当前段消息证据满额后拒绝新消息，原消息的幂等重试和未确认消息的确认继续可用。管理员可在全部消息确认、全部契约终局后显式开启下一个有限活动段，完整保留旧请求及契约身份；首次成功轮换使用 schema v2 清单，见 `RADIO_JOURNAL_ROTATION.md`。它仍不是无限期自动轮换的日志服务。

消息sequence按固定协议分别保留。命令确认时，跨协议的相同发送者/tick/sequence必须显式选择协议；短格式仅接受唯一匹配，详见`RADIO_ACKNOWLEDGEMENT.md`。

2026-11-26 新增8项单元回归。修复前仅增加信箱数量观测方法，就复现了两条失败：10,000个不同身份依次加入/退出后仍保留10,000个空信箱；最后一条消息确认后，发送者与收件人的两个空信箱仍未清理。原代码、测试与失败输出保存在 `evidence/p4/mailbox-retention/baseline/`。这是代码回归复现，不是实服事故或堆使用量测量。

其余测试覆盖候选隔离、离线恢复、65个离线收件人与64个在线端点的独立准入、单信箱满额拒绝与确认后重试、协议更换后不可读取/确认旧协议消息。既有12项 `RadioServiceTest` 继续覆盖发送、确认、收件、超时、关闭的写盘失败和旧v1待履约样本。

两项完整容量样本使用实际编解码器、文件保存与历史恢复校验，得到以下文件大小：

| 固定样本 | 文件字节数 |
|---|---:|
| 4,096个离线收件人各一条待确认消息；64字符token、19位tick与10位sequence | 5,382,703 |
| 上述消息全部确认，保留4,096条消息与8,192个事件 | 5,046,831 |
| 256份活跃契约，4,096条已应用并确认消息 | 7,073,798 |
| 上述契约重启后全部超时，契约事件增至4,352条 | 7,138,312 |

契约样本为每份offer/accept各一次、14次部分履约，随后通过 `RadioService` 推进至第205步并关闭，再次恢复核对两份完整快照。容量样本均小于16 MiB，但不构成所有合法数据组合的空间上界证明，也不证明服务端吞吐、tick时延、真人通信体验或长期网络容量。本批没有新增Paper/Folia实服证据。

完整构建、旧格式回归与工具检查见 `evidence/p4/mailbox-retention/summary.json`。各阶段的其余验收继续以 `PHASE_STATUS.md` 为准。
