# Arena 草稿工作区生命周期

P7草稿工作区由`ArenaDraftSessions`管理，控制器负责玩家命令与事件。服务器最多保留64个打开的草稿工作区，每位玩家最多一个；作者和共享编辑者都占一个名额。文件中的作者/草稿预算、schema和hash保持原规则。

## 准入、关闭与断线

`create`、`open`和`clone`在读取/写入草稿之前检查服务是否关闭、玩家是否已有工作区及总名额。准入检查与存储操作使用同一个服务监视器；两个并发请求不能抢占同一个最后名额，拒绝的新建/克隆不会留下文档或作者目录。失败不会发布会话，原有其他玩家工作区保持不变。

玩家正常退出或TCP连接断开时移除其工作区，释放撤销历史。未保存修改丢弃，已提交的草稿不改写；再次登录后使用`arena open <id>`加载最新已保存版本，并重新校验编辑许可。只读公开许可不等于草稿编辑许可。主动`arena close`仍拒绝未保存修改，`arena close discard`明确丢弃；undo回到已保存状态后可正常关闭。

插件关闭后拒绝新的打开、创建、克隆、保存和提交。已经进入的同步存储操作先完成，关闭/断线再清除工作区；操作不能在清理后重新放回会话。旧工作区引用不能通过已关闭服务保存。此串行范围只管理草稿会话，不替代比赛worker目录锁，也不提供多个store实例/进程或网络盘的写入排他。

## 保存与提交

保存成功后更新base hash、清除dirty和undo历史；写盘失败、协作者冲突或授权撤销时保留原工作区、修改与撤销历史，文件保持最后一次成功提交。授权仍由`ArenaRulesetStore`按照磁盘上当前文档检查。冲突需要重开最新文档，不能通过旧会话覆盖其他人的修改。

未保存的工作区不能提交审核。提交使用已保存的ID和hash；审核记录写入失败可以重试，或断线后重开已保存草稿再提交。审核/发布身份和独立审核要求沿用现有存储规则。

## 自动验证

13项服务测试覆盖断线重开、关闭准入、共享草稿64名额、未保存关闭/undo、创建/克隆/保存/提交的真实文件写入失败、协作者冲突/撤销、两个请求竞争最后名额、同玩家并发创建，以及关闭/断线等待已准入存储操作。最初机械提取原控制器的会话逻辑后，前三条生命周期测试失败；失败日志与提取源码保留，不称为实服故障记录。

实服探针通过真实客户端创建/共享/编辑草稿，验证冲突保留双方修改、TCP断线后重开、撤销后不能重开、作者重连丢弃未保存修改、独立OP审核与许可克隆。使用已接受EULA的独立目录，示例：

```sh
python scripts/server_smoke.py --kind paper --server-jar /path/to/paper.jar \
  --plugin-jar stargenesis-paper/target/stargenesis-paper-4.0.0-SNAPSHOT.jar \
  --directory .work/arena-draft-paper --port 25673 --max-players 8 \
  --player-workflow --client-script scripts/offline_client_arena_draft_smoke.cjs \
  --node-modules /path/to/node_modules
```

2026-11-26在Paper1.21.11-132及Folia1.21.11-14上运行，两个平台的五项检查全部通过，最终草稿文件字节一致，发布文件与独立审核身份核对通过。Java21/25各478项测试通过。首轮Paper客户端因宿主原生内存不足在连接前退出，失败与重试日志均保留，见[本批次证据](evidence/p7/draft-lifecycle/summary.json)。

实服三客户端流程不验证64名额规模、多个Folia区域、真人创作体验或跨重启审核。当前文件读写仍同步执行；慢磁盘可能延迟命令与关闭，不能用这些功能测试推断生产吞吐或关服时延。
