# 工作线程关闭与目录所有权

P1实验室、P5生态、P6工厂和P8竞技场比赛通过`PersistentWorker`运行。每个服务先取得自己的持久目录所有权，再读取服务状态；构造失败时释放已取得的所有权。三个命令服务继续保持一个工作线程和128条待执行命令预算，实验室保持一个定时工作线程。

## 停止顺序

1. 控制器标记关闭，停止接受新操作和投递玩家响应。已经进入实体/全局调度器的响应在执行时再次检查关闭状态。
2. 工作线程停止准入，最多等待5秒排空已接受命令。实验室把最终保存排在已有工作之后，仍由拥有模拟世界的线程执行；之后的周期tick不继续运行。
3. 超时或调用方被中断时取消尚未执行的任务，中断当前任务，再等待最多1秒。取消不是完成确认；已开始的操作可能尚未结束，也可能已经原子提交。
4. 只有执行器终止才释放目录锁。未响应中断的任务仍持有目录，新实例启动被拒绝，避免旧操作与新实例覆盖彼此的文件。晚到写入结束后可重新启动；进程退出由OS释放锁。

`ShutdownResult`记录终止、目录释放、是否请求强制中断、取消数量和调用方中断。调用方中断标记保留。插件逐服务清理，单个运行时异常不阻止其余服务关闭；只有所有服务成功停止且实验室/radio最终保存成功才记录`StarGenesis stopped cleanly`。未完成时记录明确错误，不能把`shutdownNow()`返回当作线程已经退出。

排队但未开始的命令只存在于内存，关闭超时或进程崩溃后不恢复。重启读取最后成功原子提交的文件；用户可从dashboard/replay核对结果。实验室最终保存失败保留最后有效检查点，仍可能丢失其后的未保存步骤。生态已接受命令仍顺序排空；P6工厂/P8比赛现在将命令绑定玩家连接，断线、重连和关闭时跳过尚未开始的旧连接命令，已开始的操作可继续提交。关闭后的玩家通知不影响已提交结果；满队列退出清理和恢复规则见`PLAYER_COMMAND_LIFECYCLE.md`。

## 目录锁合同

| 服务 | 相对插件数据目录 |
|---|---|
| Lab | `labs/lab/.worker.lock` |
| Ecology | `ecology/.worker.lock` |
| Factory | `factory/.worker.lock` |
| Arena比赛 | `arena-matches/.worker.lock` |

文件保持存在，不删除、不改成存档，也不计入比赛JSON目录容量。真实路径用于归一化身份，目录或锁文件的直接符号链接拒绝。OS文件锁排除不同进程；同一JVM还使用`dev.stargenesis.runtime.workerLease:<real lock path>`字符串系统属性预留，值为本次运行的随机token，按token释放。它跨插件类加载器共享，避免POSIX上“打开再关闭一个重复文件句柄”可能释放当前进程原有锁的问题。不能清除这些内部属性、删除持有中的锁文件，或让不遵守该协议的旧版本并行使用同一目录。

这不是存档格式迁移。原有schema、引擎版本、身份、回放hash和保存预算保持不变。单测仍可独立构造持久层；生产控制器必须先取得worker所有权。锁只保护上述后台服务，不能据此推断蓝图/程序同步编辑、真实结算provider、第三方插件、网络文件系统或多主机集群已通过验收。

## 验证范围

单元回归覆盖顺序排空、准入与队列上限、取消未运行任务、调用方中断、忽略中断、独立类加载器竞争、失败任务后续执行、最终实验检查点和真实生态存档恢复。`scripts/test_worker_directory_lock.py`使用独立JVM验证正常释放、关闭超时仍占用、同JVM/类加载器拒绝后OS锁仍有效，以及终止持锁进程后的重新获取。CI在Linux Java21/25运行探针。

```sh
python scripts/test_worker_directory_lock.py --java-home /path/to/jdk --plugin-jar stargenesis-paper/target/stargenesis-paper-4.0.0-SNAPSHOT.jar --output .work/worker-directory-lock.json
```

这些测试不等于Paper/Folia实服插件重载、玩家断线或关服验收。后续仍须在目标服务器验证关闭日志、实体调度回调和存档续跑；未响应中断的任务不能被Java安全强制终止，当前行为是隔离目录并明确报告未完成。
