# P5 封闭生态引擎 v4

`EcologyWorld` 位于 `stargenesis-sim`，纯 Java 运行，不读取 Bukkit、墙钟或全局随机源。状态由构造线程拥有。世界 ID、显式 seed、逻辑步数、基因取值、人口和检查点大小均有硬上限。

## 有限物质

世界有独立的物质账本和能量账本。反应物种单位质量乘库存后计入封闭物质账本：

```text
conservedMatter = sum(cellNutrient) + sum(cellWaste) + organismCount + reactionMatterMass
```

每个个体代表 1 个生物量单位。摄取将 1 单位营养转为 1 单位废料，繁殖将 1 单位营养转为 1 个新个体，死亡将个体生物量转回 1 单位营养，分解将有限废料转回营养。每一步都会保持物质总量不变。能量另行按下式守恒：

```text
conservedEnergy = initialOrganismEnergy + cumulativeEnergyInput
conservedEnergy = availableEnergy + organismEnergy + heatReleased
```

每一步按 `energyInputPerStep` 向有限能量池输入能量。摄取只把该池能量转入个体储能，不凭空产生能量；代谢和死亡释放的剩余能量计入散失热；繁殖把父体储能转移给子代。能量与物质是两个独立的账本，摄取与转化不会改变能量守恒公式。

## 空间食物网与局部反馈

每个世界使用固定的 8×8 环形栖息地，格子按行优先编号为 0–63。新世界按 seed 偏移把营养分配到最多 64 个食物格，格数为创始种群规模与 `ceil(initialNutrient / 8)` 中较大值，个体起始在对应资源格。营养、废料和个体位置都属于模拟状态。

个体只摄取所在格的营养，摄取产生的废料留在该格，死亡也把生物量归还该格。每一步每格最多按 `decompositionPerStep` 把废料转回营养。生态反应产生的 `ecology:nutrient` 进入当前营养最少的格，seed 和 tick 用于稳定的并列选择。繁殖需要所在格有营养，且该格个体少于 8 个；世界级 `maxPopulation` 仍限制总种群。

现存个体在步末考察本格和四个相邻格，以营养量除以该格个体数加一后的供给量选择位置，并优先降低拥挤程度。seed、tick 和个体 ID 决定候选方向顺序，因此同一设置可逐步重放。局部摄取、局部分解、食物供给驱动的移动和每格繁殖上限共同形成生态密度反馈。移动只改位置，不改变物质账本。

## 有界质量平衡反应网络

`MatterReactionNetwork` 使用稳定 `DesignId` 和正整数单位质量表示物质；配方以有界整数计量系数列出反应物和产物。建网时逐条验证两侧质量相等、引用的物质存在且反应 ID 唯一，因此运行期不能通过配方增加或删除总质量。`EcologySettings` 保存反应定义与初始库存，`EcologyWorld` 每步执行网络并把当前库存纳入物质总量、状态哈希和检查点。

每次 `applyStep` 复制并校验输入库存，按反应 ID 字典序依次执行。单条反应在自身上限、现有反应物和全局预算内尽可能触发一次批次；较早反应的产物可供同一步中较晚的反应使用，反过来则须等下一步。结果包含固定顺序的库存快照、每种已触发反应的次数和守恒质量总量。

硬上限为 64 种物质、48 条反应、每条反应两侧各 16 种物质、每种物质每单位最大质量 1,000,000、每项配方系数 1,000、每种物质库存 1,000,000、每步总计 1,024 次反应以及总质量 1,000,000,000,000。反应定义和库存已进入 `EcologyWorld` 步骤、状态哈希和持久检查点；这些上限保证最大反应网络、256 个创始个体及完整检查点能保持在 65,536 字节格式边界内。`EcologyWorld` 允许在步数上限前增删反应，重建网络时先验证整张网络且不改变总物质。Paper 配方工坊每侧提供最多 16 个物质槽，每槽系数为 1–16，玩家可编辑多个反应物和生成物；同侧重复物种会按 ID 合并，保存前严格验证物质存在、配方非空和质量平衡。每步触发上限也可独立调整。

Paper 生态会话提供固定目录 `ecology:biomass`、`ecology:detritus`、`ecology:mineral`、`ecology:nutrient` 和 `ecology:toxin`。新生态的 48 单位生物量是有限初始库存。每步反应完成后，单位质量为 1 的 `ecology:nutrient` 库存全部转入营养最少的栖息地格，随后才进行本地生物摄取；该转移计入同一守恒物质账本，因此玩家反应能真实供养或改变生态。旧无反应目录的会话恢复时安装零库存目录，保留其既有守恒总量。

初始物质由 `initialNutrient + founders.size()` 产生，不存在运行期 mint。每步最多处理 256 个个体和 64 个栖息地格；最大种群 256，世界最多 100,000 步，初始营养最多 1,000,000 单位。

## 遗传程序与步骤顺序

个体基因是有限程序参数 `energyPerFood`、`maintenanceEnergy`、`lifespanTicks` 和 `maturityTicks`。效率和代谢成本为 1–4，寿命为 2–10,000 步，成熟期小于寿命。不存在玩家脚本、递归、IO 或动态类加载。

每个逻辑步严格依次执行：

1. 向能量池计入本步输入，按反应 ID 顺序执行有界质量平衡反应，并把生成的 `ecology:nutrient` 转入营养最少的栖息地格。
2. 对每格按 `decompositionPerStep` 上限把本格废料转成营养。
3. 按个体 ID 升序为个体增加年龄；只在所在格有营养时摄取 1 单位并从能量池增加对应能量，然后支付代谢成本。能量不足时饥饿死亡；达到寿命的个体在支付当步代谢后死亡，死亡生物量回到原格。
4. 按剩余个体 ID 升序在所在格繁殖。个体须达到成熟期、能量不少于 `reproductionEnergy`、所在格有营养、所在格种群少于 8，且世界种群未达上限。繁殖扣除父体能量并把 1 单位本格营养变成子代生物量。
5. 现存个体依据相邻格营养供给和局部种群密度移动一格，将逻辑 tick 加一，输出生态事件、反应事件、统计和状态哈希。子代从下一步才开始摄取。

突变率使用千分比。每次繁殖先通过由 seed、逻辑 tick 和父体 ID 导出的固定 `mix64` 值判断突变，再以同一确定性输入选择四个基因之一并改变 1。达到基因边界时反向改变；每次结果仍满足全部基因约束。等 seed、设置与创始基因产生相同事件、统计和哈希。

## 检查点和统计

快照按个体 ID 排序并防御复制，64 格状态按编号固定排序。统计包括种群、不同基因型数量、平均能量、平均摄取效率、累计出生/死亡、摄取/分解量和守恒物质总量。SHA-256 状态哈希覆盖引擎版本、完整设置、tick、逐格物质库存、累计计数、个体 ID、栖息地位置、基因、年龄与能量。

`EcologyCheckpointCodec` 使用大端二进制格式、magic、格式版本 4 和 UTF-8 严格解码，编码大小最多 65,536 字节。v4 保存全部 64 格的营养/废料库存和个体栖息地位置。解码拒绝未知版本、越界计数、尾随数据、非法配方、任一账本不守恒、统计不匹配或哈希不匹配。v3 解码器先按旧状态规则验证 `ecology/3` 哈希，再把原有全局库存和个体映射到兼容格 0；v2 解码器先按旧状态规则验证 `ecology/2` 哈希，保留能量基线、可用能量、累计输入和散失热后迁移；v1 解码器先验证 `ecology/1` 哈希，然后把旧存档当前所有个体的储能总和作为新能量基线，旧格式未记录的可用能量、累计输入和散失热从零开始。Paper 写入新版 PDC 键后移除旧键，解码失败时保留旧键。哈希用于状态完整性验证，不是作者签名或防止拥有数据写入权限的服务端管理员伪造状态。

`/genesis ecosystem` 提供个人 Inventory 面板。玩家选择一个个体后，可在四项基因按钮上左键增加、右键减少一个单位；玩家编辑在边界夹断，不改变当前物质总量，也不推进逻辑步。配方工坊的每个物质槽可循环选择物种或置空，Shift 左键/右键增减计量系数；最多编辑两侧各 16 个物质槽，并在保存时合并重复物种、验证总质量。玩家可调整每步触发上限、循环选择并删除已保存反应；配方编辑与生态步都写入同一玩家检查点。单次步进按钮推进一个逻辑步，检查点按玩家 UUID 绑定并写入其 PersistentDataContainer。`/genesis ecosystem reset` 创建新生态。隔离 Paper/Folia 离线客户端流程已验证一次玩家检查点经断开、正常停服和重启后恢复；真人体验评估及长周期或崩溃保存耐久性仍待完成。当前面板不访问世界方块或真实物品库存。

## 服务器共享生态

`/genesis ecosystem share menu` 打开共享组 Inventory。组列表每页显示最多 34 个当前玩家所属组；点击组可查看所有者、成员、步数和状态哈希。所有者可在详情中邀请或移除在线成员，成员可查看组状态并推进一步。成员可自行离组，所有者解散须再次确认。菜单只列出在线玩家作为邀请对象；离线成员可通过命令按完整 UUID 邀请。命令入口包括 `share create`、`share list [page]`、`share add <group-id> <player-uuid>`、`share remove <group-id> <player-uuid>`、`share leave <group-id>`、`share disband <group-id>`、`share status <group-id>` 和 `share step <group-id>`。最多 8 名成员，所有者不能移除或离开该组。成员操作权限按玩家 UUID 检查。

共享组与个人 PDC 检查点分开保存。服务器最多保存 128 组，每个 `ecology-groups/<group-uuid>.eco` 文件内含最多 65,792 字节的 `ecology-group/1` 记录、最多 8 个成员 UUID 和一个 v4 生态检查点。外层 SHA-256 覆盖组记录，内层生态 codec 校验完整生态账本与状态哈希。命令和快照读取在 Paper/Folia 全局调度器上串行执行；Inventory 创建和更新回到对应玩家调度器。每次变更先编码并原子替换文件，成功后再更新内存状态。启动扫描只枚举小写规范 UUID 命名的 `.eco` 文件；其他文件名会被忽略。被枚举文件若损坏、越界、使用未知版本，或文件名中的组 UUID 与记录 UUID 不符，启动恢复失败。Paper/Folia 三客户端离线自动流程覆盖组菜单、邀请/移除、共同步进、正常停服重启恢复，以及个人 v4 PDC 连续两次正常重启后的恢复，证据见 `docs/evidence/p5/shared-ecology-paper.json` 与 `shared-ecology-folia.json`。真人协作与长时间或异常/崩溃保存耐久性仍待验证。

## P5 缺口

当前实现提供可编辑且可遗传的有限基因参数、确定性突变、物质与能量双账本、玩家可编辑的多物种输入输出配方、反应营养产物到局部食物网的连接、8×8 确定性栖息地、局部密度反馈和最多 8 人的服务器共享生态组。Paper/Folia 离线多客户端已验证共享管理菜单、邀请/移除、共同步进、正常重启恢复，以及个人 v4 PDC 连续两次正常重启后的恢复。真人协作、长时间与异常/崩溃保存耐久性和真人体验评估尚未完成，P5 保持开发中。
